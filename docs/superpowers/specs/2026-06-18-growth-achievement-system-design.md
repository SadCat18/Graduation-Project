# SkateHub 用户成长与成就系统设计

## 1. 目标

在现有经验值、等级和成长日志基础上增加每日签到、排行榜和成就勋章，形成可演示的用户成长闭环：用户完成行为，获得经验，影响等级与榜单，并解锁可收藏的勋章。

第一版不增加可消费积分、积分商城、勋章交易、后台勋章编辑器或跨时区签到。

## 2. 已确认规则

### 2.1 每日签到

- 每个用户每天只能签到一次，日期统一按 `Asia/Shanghai` 计算。
- 每次签到获得 5 点经验。
- 连续签到每满 7 天额外获得 20 点经验，即第 7、14、21 天等触发奖励。
- 连续签到天数不会在第 7 天清零；漏签后，下一次签到从连续 1 天重新计算。
- 页面展示今日签到状态、连续签到天数、累计签到天数和本月签到日历。
- 重复请求按幂等方式返回当前签到结果，不重复发放经验。

### 2.2 排行榜

- 经验总榜按用户当前总经验倒序排列。
- 本周活跃榜按当前自然周内获得的经验合计倒序排列，周一 00:00 开始新一周。
- 同分时按最后一次获得经验的时间升序排列，再按用户 ID 升序排列。
- 榜单展示名次、头像、用户名、等级和经验，不展示手机号等敏感字段。
- 榜单返回当前用户的名次，即使当前用户不在当前页。

### 2.3 勋章

勋章只作荣誉展示，不发放额外经验。首批勋章固定如下：

| 编码 | 名称 | 条件 | 稀有度 |
| --- | --- | --- | --- |
| `FIRST_CHECKIN` | 初来乍到 | 首次每日签到 | 普通（灰） |
| `STREAK_7` | 坚持训练 | 连续签到 7 天 | 稀有（蓝） |
| `CHECKIN_30` | 日积月累 | 累计签到 30 天 | 传说（金） |
| `FIRST_POST` | 初次发声 | 成功发布第一篇帖子 | 普通（灰） |
| `POST_10` | 内容达人 | 累计成功发布 10 篇帖子 | 史诗（紫） |
| `FIRST_ACTIVITY_CHECKIN` | 初次约板 | 首次完成活动现场签到 | 普通（灰） |
| `ACTIVITY_CHECKIN_3` | 约板达人 | 累计完成 3 次活动现场签到 | 稀有（蓝） |
| `PLACE_REVIEW_3` | 场地探索者 | 累计成功提交 3 条场地评价 | 稀有（蓝） |

视觉规范为街头贴纸风格、不规则盾牌轮廓、按稀有度使用灰蓝紫金配色、每枚勋章使用独立手绘街头符号。未解锁勋章显示灰色剪影、名称、条件和当前进度。

## 3. 数据设计

### 3.1 `tb_daily_checkin`

| 字段 | 说明 |
| --- | --- |
| `checkin_id` | 主键 |
| `user_id` | 用户 ID |
| `checkin_date` | 上海时区签到日期 |
| `streak_days` | 本次签到后的连续天数 |
| `base_exp` | 基础经验，第一版固定为 5 |
| `bonus_exp` | 周期奖励经验，未触发时为 0 |
| `create_time` | 签到时间 |

建立 `(user_id, checkin_date)` 唯一索引和 `(user_id, checkin_date desc)` 查询索引。

### 3.2 `tb_badge`

保存勋章编码、名称、说明、稀有度、图标编码、排序值和启用状态。首批数据由数据库初始化脚本写入，第一版不提供后台编辑入口。

### 3.3 `tb_user_badge`

保存用户 ID、勋章 ID、解锁时间。建立 `(user_id, badge_id)` 唯一索引，并按用户和解锁时间建立查询索引。

现有 `tb_user_growth_log` 继续作为经验发放的去重依据和周榜统计来源，不新增第二套积分账本。

## 4. 后端结构

- `CheckinService`：负责签到幂等校验、连续日期计算、签到记录和经验发放。
- `LeaderboardService`：负责总榜、周榜和当前用户排名查询。
- `BadgeService`：负责勋章条件计算、幂等发放、勋章列表和进度查询。
- 现有 `UserGrowthService`：继续统一写入成长日志并更新用户经验。

签到记录、成长日志和用户经验更新必须位于同一事务中。数据库唯一约束作为并发重复签到的最终防线。

发帖、活动现场签到、场地评价和每日签到成功后发布业务事件。勋章检查在主业务提交后执行，并使用独立事务保存；勋章检查失败只记录错误，不能回滚已经成功的主业务。后续用户查询勋章时再次校验可补发遗漏勋章。

## 5. API

所有接口均要求用户登录：

```text
POST /api/user/checkin
GET  /api/user/checkin/status
GET  /api/user/checkin/calendar?month=YYYY-MM
GET  /api/user/leaderboard?type=total|weekly&page=1&size=20
GET  /api/user/badges
```

签到响应包含今日状态、连续天数、累计天数、本次基础经验、奖励经验和总经验。勋章响应同时返回已解锁状态、解锁时间、目标值和当前进度。

非法月份、榜单类型或分页参数返回统一业务错误。分页大小设置上限，避免一次读取完整榜单。

## 6. 前端设计

在现有个人中心增加“成长中心”标签，不新增一级导航。成长中心包含：

1. 顶部经验等级卡和升级进度条。
2. 每日签到卡、本月日历、连续和累计签到数据。
3. 经验总榜与本周活跃榜切换区，并突出当前用户。
4. 按稀有度和解锁状态展示的勋章墙。

勋章图案实现为本地 SVG 组件，通过 `iconCode` 映射，不依赖外部图片服务。解锁成功后显示短暂弹层，包含勋章图案、名称、稀有度和关闭按钮；动画尊重 `prefers-reduced-motion`。

## 7. 错误与安全处理

- 所有用户 ID 从认证上下文获取，客户端不能指定领奖用户。
- 重复签到和重复发放勋章均按幂等结果处理。
- 排行榜使用 DTO 白名单返回字段，禁止序列化完整用户实体。
- 连续签到计算只依赖数据库中的最近签到日期，不依赖客户端时间。
- 并发唯一约束冲突后重新查询当天记录并返回成功状态。
- 内容删除不回收已获得勋章，勋章代表用户曾经完成过条件。

## 8. 测试范围

后端测试覆盖首次签到、重复签到、并发签到、跨日签到、漏签重置、连续第 7 和第 14 天奖励、事务回滚、两个榜单的排序与个人名次、八枚勋章的解锁和重复发放、未认证访问及参数边界。

前端测试覆盖签到状态和按钮禁用、本月日历、经验进度更新、榜单切换与当前用户突出、已解锁和未解锁勋章状态、解锁弹层及减少动态效果设置。

## 9. 验收场景

使用测试用户完成一次签到后，页面立即显示新增 5 点经验和更新后的等级进度；构造连续第 7 天签到时额外增加 20 点经验；经验变化能反映到总榜或周榜；完成指定业务条件后展示对应街头贴纸勋章，刷新页面后解锁状态仍然存在，重复请求不会重复增加经验或勋章记录。
