# 滑板选板助手：开发任务与派发说明

日期：2026-10-09  
对象：任务负责人及其派发的开发、数据整理和测试人员

项目：SkateHub（Spring Boot + Vue）

## 1. 目标与授权边界

新增“选板助手”，帮助初学者根据预算、用途和偏好选择第一套双翘滑板。用户可以获得成品整板或配件组装方案，比较差异、替换组装配件并保存配置。

核心价值是可解释的规则筛选、完整配件计算与搭配检查，不能仅实现器材展示或由 AI 生成一段推荐文字。

本文供负责人组织后续开发，不表示代码已经完成，也不构成生产部署、数据库导入、外部付费调用的授权。本次文档交付不派发人员、不启动编码。负责人收到后应先完成任务登记、范围确认及接口契约，再按下述依赖安排工作。

## 2. 第一版范围

### 必须交付

- 一级入口“选板助手”，与现有导航、登录和个人中心风格一致。
- 需求填写：人民币预算、主要用途、偏好、推荐类型；鞋码选填。
- 成品整板和组装方案分标签页展示，每类最多三套有实际差异的方案。
- 方案详情、最多三套跨类别对比。
- 组装配件替换、重新计价、重新检查及连带调整提示。
- 登录用户保存、命名、备注和管理自己的方案。
- 器材数据、价格、搭配规则、模板的后台维护与推荐试算。
- 必要数据迁移、校验、业务测试和验收材料。

### 后续增强，本批次不派发

- AI 配置解释、带配置上下文的器材对话。
- 配置分享到社区、采纳社区建议、使用反馈。
- 配置版本比较、价格变化通知。
- 基于已有装备的升级推荐、自动抓取更新器材数据。
- 支付、购物订单、真实交易、多市场币种、长板和鱼板推荐。

## 3. 用户流程及页面

填写需求 → 推荐结果 → 方案对比或详情 → 调整组装配件 → 保存 → 我的方案。

| 页面 | 必要内容 |
|---|---|
| 选板助手 | 预算、用途、偏好、推荐类型、选填鞋码；说明范围为双翘滑板 |
| 推荐结果 | 需求摘要、修改需求；整板/组装标签页；方案价格、理由、限制及状态 |
| 配置详情 | 具体规格、数量、计价口径、来源日期、检查结果；组装替换入口 |
| 方案对比 | 总价、主要用途、关键尺寸、轮子特征、安装便利性、待确认事项 |
| 我的方案 | 名称、备注、保存时价格、保存时间；查看、复制为新方案、删除 |
| 器材浏览/详情 | 复用或扩展已有入口，展示规格与来源，支持进入配件替换流程 |

输入选项：

- 用途：基础动作练习、日常滑行、两者兼顾。
- 偏好：容易上手、滑行舒适、价格实惠、不确定。
- 推荐类型：成品整板、自己组装、都可以。
- “容易上手”指安装省心、适合入门用途及说明清楚，不等同于某个尺寸或高价产品。
- 鞋码必须注明单位/尺码体系；暂未建立有依据的映射时不参与排序，仅记录，不臆造尺寸关系。

## 4. 数据基线与整理要求

来源目录：`docs/equipment-data/`。以实际 `equipment.json` 为准，README 不能代替数据核查。

本次文档编制时读取到：50 条记录；26 条含国内价格，22 条国内价格为数值。README 仍写 45 条且部分价格缺失说明已落后。上述统计只是文件检查，未重新联网验证商品真实性、价格或库存。

已知缺口：

- 螺丝和垫片缺少国内价格。
- 部分价格为区间或“起”，不能作为任意规格的精确总价依据。
- 同一记录混合多个尺寸，需拆出具体可选规格。
- 部分桥的单只/一对计价尚未确认。
- 搭配规则未形成独立、可执行且有来源的规则数据。

规范要求：

1. 分开产品型号、可选规格、价格记录和搭配规则；每个推荐项必须对应具体规格。
2. 金额采用十进制定点表示或最小货币单位，禁止浮点累计误差；国内预算只使用有效 CNY 价格。
3. 明确包装数量、计价单位、所需数量与实际购买包装数。总价按实际需购买的包装计算；不得直接把单只桥价当成一对。
4. 区间价、“起”价保留作展示，未确认具体规格价格前不得用于精确预算推荐。
5. 必需件缺价时不能输出完整、已验证的组装总价。若无需垫片，不强制添加；若规则要求添加，必须计入数量和价格。
6. 保留原始单位、标准化单位、来源链接、采集日期、适用规格、有效期和核实状态。
7. 品牌官网显示 CNY 不自动等于大陆到手价；配送、税费和市场口径待核实的价格不能标成已确认国内总价。
8. 图片链接及授权状态保留；不默认下载或具有使用授权。暂缺图片时支持无图展示。
9. 修订说明文件与数据统计，保留整理前后的映射及缺口清单，不以猜测补全参数。

当前表的文本字段可继续支持展示，但不能仅把规则和价格塞入描述文本供程序猜测。负责人选择结构化扩展方案并记录理由，兼顾现有器材接口。

## 5. 推荐与检查契约

### 5.1 推荐过程

组装采用经核对的基础模板：基础动作入门、日常滑行入门、综合入门。模板固定选择范围与条件，型号从有效数据筛选。

顺序：完整性与规则检查 → 预算筛选 → 主要用途 → 用户偏好 → 条件接近时价格与资料完整性 → 去重并挑选差异方案。

- 不要求花完预算，不把价格高当成更适合。
- 不凑满三套，不以同配置换图案作为差异方案。
- 不使用 AI 生成价格、配件数量、兼容结论或主推荐清单。
- 使用有界候选与确定性排序，避免无界组合枚举；同数据同输入应能复现结果。
- 推荐理由由命中的规则和产品事实形成，不展示无依据的“匹配度 98%”。

### 5.2 检查规则

| 检查 | 依据与限制 |
|---|---|
| 板面与桥 | 品牌官方适配区间或已核对的实际轴宽；不得直接比较型号编号 |
| 轮子、桥与垫片 | 使用有明确范围的厂家资料；咬轮受桥松紧、胶套及使用影响，不保证绝不会发生 |
| 垫片与螺丝 | 对应安装说明与长度条件 |
| 砂纸 | 覆盖所选板面的尺寸 |
| 完整性 | 板面、两只桥、四颗轮子、八颗轴承、砂纸、固定件，以及条件性必需件 |

检查结果至少区分：符合已知规则、明确不兼容、使用建议、资料不足。每条结果有解释和依据。

关键参数不足的组装配置不能进入“已验证”推荐。软性建议可进入结果，但明确展示。成品整板按厂家完整商品筛选，不因内部参数不全就虚构本站验证结论。

### 5.3 边界状态

- 预算不足：明确无符合方案，可展示当前器材库最低可行方案与差额，不自动提升预算。
- 数据不足：说明缺价/缺规格/缺规则；不能误报为预算不足。
- 成品有结果、组装无结果：两个标签页分别反馈。
- 商品下架、优惠过期、价格待核实：停用对应报价参与新推荐。
- 替换配件：重新检查整套方案；需要连带替换时先提示，用户确认后处理，不能悄悄改变其他配件。

## 6. 保存、权限与价格快照

- 推荐、浏览和对比可匿名使用；保存要求登录并保留当前操作上下文。
- 保存由服务端重新核对具体规格、价格版本与检查结果，不信任客户端提交的总价或通过状态。
- 保存需求、配件及数量、参考价格和采集日期、规则/模板版本、检查结果、名称和备注。
- 保存时价格为快照，不随数据更新覆盖。最新价格/状态如展示，必须与快照分开。
- 用户只能读写自己的方案；后台维护仅管理员可用。
- 并发替换或过期响应不得覆盖更新后的页面结果。保存时价格变化应提示并展示新结果，不能无提示保存旧计算。

数值阈值只能在来源核对后冻结。资料缺口如实登记，并继续可独立开展的工作，不让开发者自行编造。

## 9. 验收场景

1. 已核对的完整配置：包装数、配件数量、总价及预算差额准确。
2. 同预算变更用途/偏好：在数据支持时排序或配置合理变化，理由对应规则；无合适候选时明确说明。
3. 提高预算：扩大可选范围，不强制使用更贵配置。
4. 更换板面：桥适配检查同步更新；更换轮子：相关垫片/螺丝提示更新。
5. 不兼容、缺价、参数不足、过期优惠、下架、无候选分别正确反馈。
6. 成品和组装结果独立，跨类别对比最多三套；不重复凑数。
7. 匿名用户登录后可继续保存；用户不能读取或修改他人方案。
8. 客户端伪造总价/检查通过被拒绝或由服务端纠正；保存期间数据变更可见。
9. 历史方案不被新价格覆盖；复制创建独立方案，删除仅影响本人。
10. 快速连续替换、返回页面、接口失败不显示过期结果或假成功。
11. 原有器材浏览、AI 教练、社区、活动、个人中心和后台相关入口无明显回归。

数据整理完成后准备至少三套不同用途/预算的完整组装样本和成品样本，记录精确规格、数量、总价与依据。若实际数据无法支撑三套，报告缺口，不制造通过样本。

测试包括后端业务/权限与关键前端流程；构建成功不代替端到端业务验收。运行环境不可用时，保留已验证范围并明确联调未完成，不宣称上线可用。
