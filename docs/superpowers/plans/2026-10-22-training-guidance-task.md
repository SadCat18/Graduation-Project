# 训练执行与指导模块：任务计划

日期：2026-10-22  
状态：待执行；本次仅编制文档，未修改业务代码、执行迁移或派发任务。  
项目：SkateHub（Spring Boot + Vue）  
适用对象：任务负责人、后端、前端、教学内容整理及测试人员。

## 1. 目标与范围

将训练计划完善为“选择目标 → 安排任务 → 执行练习 → 提交反馈 → 获得指导 → 确认调整 → 阶段复盘”的完整过程。

系统根据用户记录分析执行情况，提供有来源的教学指导和明确的调整建议。用户自报与动作自评不能作为客观能力认证，练习时长、任务完成率和动作自评分别展示。

### 第一版必须完成

- 基于已维护模板建立个人计划，收集目标、当前自评水平、每周训练日、单次可用时间。
- 今日任务、教学步骤、建议练习量、动作自查和教学资料。
- 结构化反馈、多次练习记录及进度统计。
- 基于反馈的规则指导、教学资料检索及 AI 辅助解释。
- 时间调整、任务巩固、阶段推进三类建议；明确展示差异，用户确认后生效。
- 训练历史、调整历史、暂停与恢复。
- 后台内容、规则和版本维护。
- 迁移、权限、幂等、业务回归与流程验收。

### 本批次不做

视频自动识别、动作自动评分、视频人工点评工作台、教练预约、外部消息推送、社交挑战、自由生成高强度训练方案、医疗诊断。

不新增持续运行的定时任务或外部付费调用，除非执行阶段另有明确授权。站内遗漏提示可在访问页面时计算。

## 4. 反馈结构与状态语义

### 4.1 每次练习反馈

- 完成情况：完成、部分完成、未开始。
- 实际练习分钟：非负，未开始为零；允许合理的小数与否、最大值由契约统一。
- 主观难度：轻松、适中、困难；未开始可不填。
- 动作自查：每任务两三个具体问题，答案允许是/否/不确定/不适用。
- 困难原因：时间不足、场地不合适、动作困难、身体不适、其他；支持多选和可选文字。
- 练习日期、任务实例、记录时间；补录政策由契约确定，不能覆盖原始提交时间。

自查问题随任务版本保存，不因后台修改导致历史答案失去含义。

### 4.2 分离三类状态

1. 任务执行：待练、部分完成、已完成等。
2. 动作自评：未评估、需巩固、自评稳定、不确定等；页面标明自评。
3. 建议处理：待确认、已接受、已拒绝、已失效。

具体枚举在 T00 冻结。不能用一条反馈同时隐式完成任务、推进阶段并发放多次奖励。

### 4.3 计划状态与统计

支持进行中、暂停、完成、退出；区分暂停后恢复与退出后重建。恢复、补练不自动清空记录。

- 任务完成率：分子/分母依据当前有效任务实例，记录统计口径；调整前后可解释，不以简单天数替代。
- 练习量：按有效练习记录累计，重复请求不能重复累计。
- 动作状态：来自用户自查，不能折算成客观能力分数。
- 漏练：已排定训练日的任务没有完成；休息日不是漏练。

用户训练日期与展示使用明确时区，默认 Asia/Shanghai；日期计算不能依赖服务器未知时区。

## 5. 指导与调整规则

| 反馈/条件 | 建议 | 行为限制 |
|---|---|---|
| 漏练一天 | 顺延至下一个可训练日 | 不把两天训练量自动叠加 |
| 时间不足 | 拆分任务、缩短单次安排或调整训练日 | 不降低动作水平、不删历史 |
| 部分完成且难度适中 | 继续剩余任务 | 不重复安排已完成部分的整套训练量 |
| 动作困难 | 保留阶段，选择已维护的分解练习与教学资料 | AI 不编造新动作或强度 |
| 完成且自查稳定 | 依据前置条件建议推进 | 必须用户确认；非掌握认证 |
| 自查不确定 | 提供自查方法并建议巩固 | 不直接判定失败或升级 |
| 长期中断 | 重新自评、复习基础任务 | “长期”阈值需说明依据并可配置 |
| 身体不适 | 安全提醒，暂停相关推进建议 | 不诊断、不加量；不能被“完成且轻松”等条件覆盖 |

实现要求：

- 安全提醒在提交反馈后立即展示；对暂停建议的确认不得延迟提醒。未处理不适反馈前，不再给出相关加量或推进建议。
- 有明确优先级及冲突处理，不能同时建议休息和进阶；缺少必要反馈时不触发推进。
- 每条建议保存触发原因、规则版本、影响任务、调整前后差异。
- 接受建议在事务中校验用户归属与计划版本，原子更新未执行安排；重复接受无副作用。
- 拒绝建议不改变安排；旧建议在计划或相关记录变化后重新校验，过期建议不可强行接受。
- 第一版优先“顺延/拆分、重复/分解、阶段推进”固定操作，不建设自由编排规则引擎。

## 6. 教学内容准备

先覆盖站姿与平衡、基础滑行、基础转向、基础刹车四类，按实际来源形成少量完整任务。

每项至少具备：适用水平、前置条件、目标、步骤、建议练习量、两三个自查问题、常见困难、对应指导、教学来源、安全提醒、阶段推进条件及适用限制。

材料可来自本站已有动作、帖子、视频描述和训练任务；核对可见性、链接、内容质量及来源。视频描述不能当作系统已理解视频动作。

推进次数、时长、难度阈值不得随意编造或声称医学/专业认证。来源不足时采用保守的用户确认机制并标注限制；内容未齐全的模板不发布。

## 7. AI 与检索集成

复用现有 AI 网关、权限、限流及会话能力，新增的训练上下文仅包含必要的本人数据。

- 传入当前任务、用户反馈、适用的规则建议和已授权可见的教学片段。
- 返回可操作解释与引用链接；教学材料当作资料而非可执行指令。
- 用户点击“这个动作遇到困难”后先预览带入的问题，再确认发送。
- AI 不能直接写计划、发奖励、改变完成状态或医学诊断；真正调整由独立规则建议接口完成。
- 无检索结果时说明缺少本站依据，可继续询问；不能伪造教学引用或假装已检查用户动作。
- AI 超时/失败不回滚已保存反馈，不阻塞记录、统计、固定教学和规则建议；支持用户主动重试，避免重复提交记录。
- 验收以真实实现为准；不把现有关键词检索描述为已完成向量化知识库。

## 8. 后台与版本

后台维护动作关联、教学任务、模板、自查问题、困难指导映射和固定调整规则。

模板支持草稿、可用、停用；发布前检查来源、必填字段、前置依赖、时长与循环依赖。

个人计划采用模板/任务版本快照。管理员编辑新版本不无提示覆盖已采用的内容；已停用资料不可继续作为新推荐依据，历史保留必要快照与状态说明。对安全纠正需明确通知并阻止继续推荐错误材料。

## 9. 数据与接口契约（T00 冻结）

负责人先确定并记录以下内容，再派发依赖开发：

- 模板/任务版本、个人计划、排期任务实例、练习记录、动作自查、调整建议和历史的数据关系。
- “多次练习”与“任务首次完成”的关系、经验奖励唯一键及旧记录兼容方案。
- 当前计划数量限制、加入/退出/暂停/恢复语义，与旧接口的兼容策略。
- 建立计划、今日安排、反馈提交、回顾、统计、历史分页、建议接受/拒绝、AI 上下文及后台接口。
- 反馈幂等键、计划版本、建议有效性、错误码、日期时区、补录和纠错政策。
- 一次训练是单任务还是多任务的反馈组织方式，以及实际分钟如何分配，避免重复累计。

建议第一版按任务实例记录反馈；重复训练新增练习记录。同一次请求重试复用幂等键。历史事实如需纠正，保留修订标记，不能悄悄覆盖已触发奖励或建议的数据。

接口响应提供服务端计算的状态、统计、允许操作及原因；前端不能自行推断推进资格。

## 11. 验收清单

- [ ] 能按训练日与单次时间建立计划，休息日不误报漏练。
- [ ] 任务有完整教学步骤、来源和自查；旧计划可按约定继续使用。
- [ ] 完成、部分完成、未开始分别正确记录；同任务支持多次练习。
- [ ] 相同请求重试和并发提交不会重复记录、重复统计或重复发奖励。
- [ ] 时长、完成率与自评分别展示；部分完成不会触发整项完成奖励或自动进阶。
- [ ] 时间不足、动作困难、自查不确定、长期中断各有正确且不冲突的建议。
- [ ] 不适反馈优先展示安全提醒，不产生相关推进建议。
- [ ] 接受建议后安排正确变化，拒绝不变；重复接受、跨用户接受和过期建议被正确处理。
- [ ] 调整不覆盖历史记录；模板升级不改变已采用的快照。
- [ ] AI 有引用，失败不丢失反馈；无资料时不伪造答案依据。
- [ ] 反馈、计划、建议和历史接口均验证用户归属，后台限制管理员访问。
- [ ] 连续切换任务、快速提交、返回页面等不显示过期结果或假成功。
- [ ] 原有计划加入/退出、打卡、经验奖励、AI 教练及相关页面完成回归。

完整演示案例：建立基础训练计划 → 部分完成并反馈时间不足与转向困难 → 保存实际记录 → 获得相关教学与拆分建议 → 查看差异并确认 → 新安排生效 → 历史记录可查。另演示一次拒绝建议和一次 AI 失败降级。

## 12. 执行与完成标准

1. 先做 T00 与内容核查，确认旧唯一约束、奖励与多次练习的兼容方式。
2. 完成数据/排期与反馈，再实现规则调整、前端、AI 和后台联调。
3. 完成有意义的业务、权限、并发与迁移测试，运行项目要求的检查。
4. 验收完整流程后交付，区分源码、离线测试、本地联调和生产证据。

保护仓库已有未提交工作，限定任务改动范围，不顺带重构其他模块。旧数据不得无备份删除或重置；生产部署、生产迁移及付费调用另行获得明确授权。

最终交付包括代码与增量迁移、教学与规则数据、接口契约、测试记录、操作说明和已知限制。存在运行环境或内容缺口时如实标注，不宣称完整验收通过。负责人对集成结果负责。
