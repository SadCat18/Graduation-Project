## 最小数据及响应约定

- 使用原 equipment.json 的50条真实采集记录及规范v1转写；保留原始/v1，创建独立参考候选。原 sourceRecordId、URL、采集日期和 RECORDED 状态不篡改，不伪造 VERIFIED。
- 数据行可增加可选 `pricingMode: REFERENCE`（缺省保持旧精确语义）；持久化内容保存该标记。标記用于区分参考启用与原精确门槛。具体应用于 products/variants/quotes/templates 等必要数据行，由后端以最小实现明确记录；不会把其他草稿自动全部启用为精确数据。
- Evaluation 增加 `pricingMode: REFERENCE|EXACT`；引用参考来源的结果必须 REFERENCE。增加 `priceAssumptions: string[]`，列出实际用于计算的包装/通用型号价等估算假设。精确结果缺省或 EXACT，历史精确快照不变。
- REFERENCE 下 `totalCents` 表示完整已知商品参考估算，不是当前含运税到手价；`budgetDeltaCents` 是参考预算差额。`priceComplete` 只表示本次选择有完整参考价格口径，不表示商品当前可购、价格有效或费用已核实。
- 没有数值的缺价项不能填0；估算总额不完整时 `totalCents/budgetDeltaCents=null`，显示 `knownSubtotalCents` 和缺项，不把已知小计称整套总价或保证预算满足。部分组装候选可以返回供用户参考，明确 DATA_INSUFFICIENT 与缺价/待确认项，不能称已验证完整方案。
- 参考结果 `validationState=REFERENCE_ESTIMATE`；保存快照 `snapshotState=REFERENCE_ESTIMATE`，资料不完整仍 DRAFT。不能使用 VERIFIED 或 MANUFACTURER_COMPLETE 表达本站已独立核验的价格/兼容结论；采集资料明确整板事实可用于成品分类。

## 参考价格与搭配

- 原始国内单一数值价格直接作为参考；不要求当前有效期/库存/运税。海外价不自动换算。区间/起价如用于估算必须标出该性质，不能隐性按精确值计价。
- 成品整板四条原记录可直接作为参考候选，资料显示售价分别580/323/446/720元；保持来源日期/链接。600元需求应能看到预算内的实际已有整板参考结果（具体排序按已有用途和偏好事实），低预算正确显示参考超预算。
- 同型号多规格的通用展示价可用于参考规格，但必须显式列为估算假设；明确不同型号/结构错配的价格不得自动套用，例如 TRUCK-001 的 Mid 价不能暗套 Standard。
- 桥/轮/轴承零售包装数量有原资料依据时采用；不明确时可明确“按一套零售包装估算”的假设，不伪称来源已证明数量。基础组装必需类别保留，螺丝/垫片等无国内价就显示未计入。
- 有已记录数值/适用范围的搭配事实可用于参考筛选；已知不兼容应排除。未知事实显示待确认，不编造物理阈值、通过声明或供应商保证。用途/偏好使用原标签或来源事实，不虚构评分依据。
- 继续服务端确定性计算、有界搜索、版本摘要、整套替换确认、本人方案权限与不可变快照。

## 前端与验收

- 结果卡/详情/对比/保存方案统一显示“参考估价”或“已知参考小计”；一句说明：按已采集资料估算，实际价格和库存请通过来源自行确认。
- 来源链接和采集日期可见；未知运税不展现为0或已包含。无需增加库存、地区、涨价监测、采购保证或报价刷新步骤。
- 后台识别参考启用状态，不能仍强迫参考数据满足旧 VERIFIED 门槛；精确启用规则保留。
- 串行后端 → 前端 → Server Test 独立审查 → 必要返工 → Server Test 发布/导入 → 总负责验收。仅更新明确候选及必要配置，保留dirty树，不提交推送。
