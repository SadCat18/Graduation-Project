# 管理员后台前端界面改造手册

本文用于指导“后台管理中心”前端界面的可视化改造。目标不是增加更多文字说明，而是让管理员在 3 秒内识别：**有什么风险、什么最急、数据是否异常、下一步该点哪里**。

适用代码范围：

- `frontend/src/views/AdminPage.vue`
- `frontend/src/views/admin/AdminReviewPanel.vue`
- `frontend/src/components/AppIcon.vue`
- `frontend/src/styles.css`

## 1. 改造目标与边界

### 1.1 目标

1. 工作台首屏以视觉信号替代模块说明文字。
2. 将“待办、风险、趋势、快捷动作”放在一屏内完成扫读。
3. 保留现有接口、权限、筛选、批量审核和 AI 审核逻辑，不重写业务流程。
4. 让审核中心、举报、帖子和资讯等高频场景共享同一套状态色、卡片和操作模式。

### 1.2 不在本期范围内

- 不修改后端审核判定规则。
- 不改变现有路由、角色鉴权和接口路径。
- 不把删除、禁用等不可逆操作放到首页直接执行。
- 不为了视觉效果新增无法操作的附件、图表筛选或虚假状态。

## 2. 信息架构

后台保留现有导航分组，但将首屏“工作台”升级为运营驾驶舱。

| 层级 | 内容 | 管理员要回答的问题 |
| --- | --- | --- |
| 决策条 | 健康状态、待处理总数、异常趋势、最后刷新时间 | 今天是否有紧急问题？ |
| 优先队列 | 高/中/低优先级待办卡片 | 先处理哪一项？ |
| 核心指标 | 用户、内容、活动、报名及环比 | 哪项运营指标变化最大？ |
| 趋势与转化 | 7 日趋势、活动漏斗、模块触点 | 问题发生在什么时间和环节？ |
| 内容排行 | 热门帖子、热门活动、举报热点 | 哪些内容值得放大或介入？ |

### 2.1 首屏布局

桌面端使用 12 列网格，推荐内容顺序：

| 区块 | 栅格 | 内容 |
| --- | --- | --- |
| 页面头部与决策条 | 12 列 | 标题、时间范围、刷新、整体健康状态 |
| 风险队列 | 8 列 | 审核、举报、场地、评价四类待办 |
| 快捷动作 | 4 列 | 审核待办、帖子治理、评论治理、资讯审核 |
| KPI 指标 | 12 列 | 4 个核心数字卡片，含趋势箭头和迷你趋势图 |
| 7 日趋势 | 8 列 | 用户、帖子、活动、报名多系列趋势图 |
| 活动转化 | 4 列 | 浏览 → 报名漏斗及转化率 |
| 热门与风险内容 | 6 + 6 列 | 热门内容排行、风险对象排行 |

移动端按“风险队列 → KPI → 趋势 → 快捷操作 → 排行”顺序单列显示；不在移动端并排展示大表格。

## 3. 视觉规范

### 3.1 状态色

统一使用语义色，禁止同一颜色表达多种业务状态：

| 语义 | 色彩建议 | 使用范围 |
| --- | --- | --- |
| 高风险 | `#DC2626` | 高风险审核、超时举报、删除警告 |
| 待处理 | `#F97316` | 待审核、待确认、数量上升 |
| 正常运营 | `#087A6D` | 已选中、主操作、正常趋势 |
| 完成 | `#059669` | 已通过、已完成、指标改善 |
| 中性 | `#687067` | 无数据、归档、辅助说明 |

每个状态色必须同时配合图标、标签或数字，不能仅依赖颜色。

### 3.2 字体、间距与卡片

- 数字优先：KPI 数值 28–36px、半粗；说明文字 12–13px。
- 页面标题 24–28px；模块标题 16–18px；正文不小于 14px。
- 卡片半径保持 14px；同层卡片之间间距 12–16px。
- 以留白、分组、细分隔线区分信息，减少厚边框和重阴影。
- 每个首屏卡片只表达一个判断：数量、趋势、风险或动作，禁止把多个功能塞进同一张卡片。

### 3.3 图表原则

- 近 7 天数据：折线图或柱状图，不再同时用长表格作为默认展示。
- 活动转化：漏斗图，直接展示“浏览 / 报名 / 转化率”。
- 分类占比：环形图；图例显示名称、数量、百分比。
- 热门内容：横向排行条，保留标题、排名、核心互动数。
- 无数据状态：展示图标、简短原因和刷新动作，不能只留空白。

建议引入 `echarts` 作为统一图表方案；图表组件需支持加载、空数据、错误和刷新状态。

## 4. 组件拆分

不要继续把驾驶舱 UI 堆叠在 `AdminPage.vue` 内。建议保留该页面负责路由、数据加载和 Tab 切换，将视觉模块拆为以下组件：

| 组件 | 责任 | 主要输入 |
| --- | --- | --- |
| `AdminDashboard.vue` | 编排工作台首屏 | stats、analytics、pendingCounts、reports |
| `AdminHealthStrip.vue` | 顶部健康状态与刷新 | pendingTotal、trendStatus、updatedAt |
| `AdminPriorityQueue.vue` | 风险和待办队列 | workbenchTodoCards |
| `AdminKpiCard.vue` | 指标、环比、迷你趋势 | label、value、delta、series、tone |
| `AdminTrendChart.vue` | 7 日多系列趋势图 | trend7d |
| `AdminFunnelChart.vue` | 活动浏览到报名的转化 | activityConversion |
| `AdminRankList.vue` | 热门/风险对象排行 | items、metric、tone |
| `AdminQuickActions.vue` | 高频动作入口 | quickAdminActions、badge |
| `AdminEmptyState.vue` | 统一空、加载、错误状态 | icon、title、action |

现有 `AdminReviewPanel.vue` 继续负责审核详情、筛选、批量审核和抽屉交互；仅将列表外层替换为更紧凑的队列或看板布局。

## 5. 现有数据映射

| 现有数据 | 改造后的展示 | 备注 |
| --- | --- | --- |
| `stats` | KPI 卡片与模块规模 | 当前只有总量；环比需新增接口字段 |
| `analytics.trend7d` | 7 日趋势图 | 使用新用户、帖子、活动、报名四个系列 |
| `analytics.productTrend7d` | 活跃度迷你趋势 | 展示在健康状态或 KPI 卡片中 |
| `analytics.activityConversion` | 活动转化漏斗 | 当前已有 views、signs、rate |
| `analytics.moduleUsage` | 模块触点排行 | 使用横向条形排行 |
| `analytics.hotPosts` / `hotActivities` | 热门内容排行 | 仅显示前 5 条 |
| `analytics.bulletinTypeRatio` | 快讯分类环形图 | 需补百分比计算 |
| `pendingCounts` / `workbenchTodoCards` | 风险优先队列 | 按风险和等待时间排序 |
| `reports` | 举报热点与处理队列 | 增加举报次数、等待时间可提升识别效率 |

### 5.1 建议补充的接口字段

为避免前端自行猜测趋势，建议聚合接口增加：

```text
GET /api/admin/dashboard-summary?range=7d

metrics: [{ key, value, previousValue, delta, deltaRate }]
pendingByType: [{ type, count, highRiskCount, oldestWaitingMinutes }]
riskDistribution: [{ level, count }]
trend7d: [{ date, newUsers, newPosts, newActivities, newSigns }]
reportHotspots: [{ targetType, targetId, title, reportCount, latestReportTime }]
updatedAt
```

接口不可用时，前端仍使用现有 `stats` 与 `analytics` 渲染基础版，不阻塞审核功能。

## 6. 交互规则

### 6.1 风险队列

- 点击待办卡片跳转到对应 Tab，并自动带入待处理筛选。
- 红色卡片只提供“查看并处理”；删除或禁用必须进入详情后二次确认。
- 卡片显示：类型图标、数量、最高风险级别、最久等待时间；不显示长描述。

### 6.2 指标与趋势

- 点击 KPI 卡片进入数据统计或运营分析。
- 图表悬浮提示展示精确值和日期；默认只显示关键图例。
- 时间范围切换应同时刷新所有首屏图表，避免模块之间使用不同时间口径。

### 6.3 审核和批量操作

- 通过/驳回动作保持现有二次确认和处理模板。
- 批量操作前展示“选中数量 + 内容类型 + 待审核数量”。
- 同一批操作只允许相同类型、相同待审核状态的数据。
- 操作完成后使用页面内 Toast 反馈成功、失败和未处理数量，避免阻塞式 `alert`。

## 7. 实施顺序

### 第一阶段：驾驶舱首屏

1. 新建 `AdminDashboard.vue`、KPI、待办和快捷操作组件。
2. 复用现有 `stats`、`analytics`、`workbenchTodoCards`、`pendingCounts`。
3. 将现有工作台的文字卡片替换为风险队列、KPI 和迷你图表。
4. 保持现有 Tab、刷新和跳转行为不变。

### 第二阶段：数据可视化

1. 引入 ECharts 并封装趋势、漏斗、环形图组件。
2. 将运营分析默认表格改为图表，表格作为“查看明细”折叠区。
3. 支持 7 天、30 天时间范围，并统一口径。

### 第三阶段：审核队列体验

1. 将审核列表改为可视化队列卡片。
2. 增加风险等级、等待时长、AI 建议摘要和批量选择反馈。
3. 将成功、失败、加载与空状态统一为页面内反馈。

## 8. 响应式与可访问性

- 小于 980px：左侧导航折叠为图标或抽屉；驾驶舱改为单列。
- 小于 760px：图表最小高度 220px，操作按钮保持可点击尺寸不小于 40px。
- 图表和状态卡片必须提供文本摘要，保证色盲、读屏和导出场景可用。
- 所有图表颜色必须具有足够对比度；红绿状态不得只靠颜色区分。
- 鼠标悬浮信息必须同时支持键盘焦点和触屏点击。

## 9. 验收标准

改造完成后应满足：

- 管理员能在首屏识别最高风险事项、待处理总量和最近趋势。
- 首屏不再默认展示长表格或大段模块说明。
- 现有审核、举报、批量处理、AI 审核、资讯审核和内容管理功能保持可用。
- 1440px 桌面端能在不滚动的情况下看到决策条、风险队列和核心 KPI。
- 390px 移动端无横向滚动，关键操作不被导航或图表遮挡。
- 图表加载、空数据、接口失败和刷新过程均有明确反馈。
- 新增组件具备单元测试；工作台、审核跳转和批量操作具备端到端测试。
