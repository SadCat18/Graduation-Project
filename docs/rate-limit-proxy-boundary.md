# Public calculation rate limits and proxy boundary

This is a code/configuration handoff. It does not assert production enablement, capacity, CIDRs, or Redis availability.

- Existing enablement remains `RATE_LIMIT_ENABLED` (application default false, Compose example true). Four exact public board calculation POST routes share one `RATE_LIMIT_BOARD_IP_PER_MINUTE` budget. The code/example default is 30 per minute; deployment must review capacity. Login/register/AI/upload/write budgets are unchanged. Tests use a synthetic budget of 2, not a proposed production threshold.
- `RATE_LIMIT_REDIS_FAILURE_DENIES_PROTECTED=true` remains the default: Redis failures return HTTP503 with a safe JSON message. Explicit false retains the existing, logged fail-open policy. No production setting was read or changed.
- `RATE_LIMIT_TRUSTED_PROXIES` defaults to empty. With no trusted proxies, only the socket `remoteAddr` determines the IP bucket. It can deliberately aggregate users behind a proxy until that deployment's direct peers have been verified; do not solve this by trusting arbitrary private networks.
- Accept only operator-verified literal IPs/CIDRs (IPv4/IPv6), comma separated. Hostnames, zones, ports and invalid prefixes are rejected. These are proxy addresses, not client allow-lists. No real deployment network is inferred here.
- With a trusted socket peer, parse X-Forwarded-For from right to left through configured trusted proxies and stop at the first untrusted hop. Discard the rest of the prefix. Malformed, empty-hop or excessively long chains fall back to the socket peer. Equivalent IPv6 literals are normalized; no DNS lookup is allowed for names.
- The repository Nginx is modeled as the outer HTTP ingress and now **overwrites** X-Forwarded-For with `$remote_addr` in all three backend proxy locations. Client-supplied prefixes cannot flow through this static topology. Backend host port publication remains absent.
- If a real deployment has a load balancer before Nginx, audit that boundary separately. The provided configuration intentionally does not trust its headers or recover a presumed original client automatically. Do not enable a generic forwarded-header filter or broad real-IP trust to compensate. Any future trusted ingress processing must strip untrusted prefixes and ensure backend `remoteAddr` is the verified immediate peer.

The public catalog snapshot uses a short independent SERIALIZABLE read-only transaction, reading metadata/version **before** rows, and finishes before CPU calculation. MySQL/InnoDB SERIALIZABLE plain SELECT may acquire shared locks; this is not a claim of zero database locking. Writers/save retain metadata-first exclusive version barriers. Local H2 concurrency/HTTP tests are evidence for their stated environment, not an actual MySQL deadlock, throughput or production load test. There is no retry loop, new cache, archive service or new dependency.
