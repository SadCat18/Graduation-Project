# PUBLIC-REMEDIATION 冻结契约 v1（2026-10-21）

本文件由总负责核对AUDIT12后冻结，开发仅在收到对应串行派发后开始。以唯一候选 `5afdd33e93e3466b4799ce48a3f9eb73248fbf9b` 为基线，后端完成交付后前端串行进入。新增字段向后兼容，保留ApiResponse外壳及既有鉴权，禁止生产数据写入/重新导入。

## C01 地区与地图（F01，前端）

地区数据加载与地图实例初始化分离。独立loading/error/ready/retry，失败不能等同于真实无下级；地图加载失败仍可使用地区控件。数据来源应具版本/覆盖范围，不要求audit阶段联网采集。可用已审查本地行政区资料或独立可重试的数据适配，不能继续由地图成功标记控制地区可用性。

省改变：立即清city/district及其旧选项；市改变：立即清district。每一级请求绑定父级值和序号，迟到响应不覆盖新选择。地区重试不得重复初始化地图。

**当前province不在Activity数据/API内；本轮默认其功能是级联选城市，界面明确“省份（用于选择城市）”。** 保留city/district/keyword/expired现有查询语义；不把省份值塞进城市字段，不将地址模糊匹配冒称省级筛选。若总负责要求独立省级查询，必须另冻结数据映射/未知省份处理后再派发，不在此次最小实现暗加迁移。地图失败不妨碍关键字与现有活动列表。

## C02 预算输入（F02，前端）

输入/报错一律以人民币元说明；现有分整数传输和parseBudget精度保持。错误放在预算或鞋码对应字段，提供关联说明，编辑该字段/清空时移除陈旧错误，非法再次提交重新校验。鞋码仅记录，不推断板宽或推荐排序。

## C03 日程覆盖（F03，后端→前端）

公开训练详情新增 `scheduleCoverage`：

```json
{"declaredDays":7,"availableDays":[1,2,3],"missingDays":[4,5,6,7],"complete":false}
```

来自真实声明和任务dayNo，availableDays去重升序；异常/越界天不算完整覆盖并保留诊断，不静默伪造完整。complete要求声明天数有效且1..declaredDays均有实际任务。字段表示资料覆盖，**不叫guestPreview，不假定登录解锁**。公开列表若展示覆盖也用相同计算；不得改变现有任务/持续天数/用户加入和进度历史。前端标题旁显著展示“计划7天，已有3天任务，剩余资料待补充”，明确列出缺日。没有内容不得显示虚构练习任务；真实完整计划显示完整覆盖。资料补全另走有依据的内容流程。

## C04 同源场地评价（F04，后端→前端）

公开场地列表、详情新增同一口径的 `localReviewSummary`：

```json
{"score":null,"count":0,"source":"LOCAL_REVIEWS"}
```

score为实际本站评价平均（沿用现有1位小数规则），count为同一真实评价集合计数；无评价为null/0。列表使用批量聚合，避免每场地单查。列表VO保留所有旧消费者必需字段，新摘要不持久化回写Place；不更改旧score/reviewCount存储、不触发历史重算任务。原字段兼容保留，前端本站评分/计数不再回退到它们。列表/详情/活动推荐及其排序展示核查所有消费者，同一真实口径；无评分排在已评价之后，无评价不能显示成0分差评。

旧4.9/203如产品仍展示，只能标“历史资料值，来源未核实”，不命名高德/外部评分、不称本站评价；最小实现可不展示旧数字。点评异步失败应为加载错误，不能显示成真实0条。没有该新字段的兼容失败状态显示“评分资料暂不可用”，不猜测数据。

## C05 社区类别（F05，后端→前端）

建议新增匿名只读 `GET /api/public/posts/categories`，返回：

```json
{"filterOptions":[{"key":"装备讨论","label":"装备讨论"}],"createOptions":[{"key":"装备讨论","label":"装备讨论"}]}
```

filterOptions为**全部公开可见帖子**的完整distinct类别与既有允许发布选项的并集（不是当前页/当前搜索结果），去空、去重、稳定排序；createOptions为共享定义的既有允许发布选项，不因历史任意字符串自动开放新建议。现有自由输入发布行为是否收紧不属本轮，不能暗加拒绝历史类别的写入验证。key沿用原始精确字符串，不添加数值ID迁移。首个“全部”为客户端空过滤，不是数据库类别。现有精确匹配API保持。

社区筛选/发布建议读取同一契约，历史未知值按原文可筛；无别名证据则aliasMap为空，不将装备讨论归并成装备分享。接口错误独立提示/重试，不能假装只有当前页类别或把无数据当失败。

## C06 装备类别（F06，后端→前端）

建议新增匿名只读 `GET /api/skate/equipments/categories`，data为完整公开有效装备distinct非空类别数组：`[{"key":"工具","label":"工具"}]`。与装备列表可见性规则一致，跨分页；不受当前筛选约束。前端“全部分类”发送空过滤；工具/砂纸有入口，清除回到完整列表。无数字分类重构。

## C07 图片与关系（F07，前端）

头像和备案图本地回退；error最多切换一次，回退再失败终止/隐藏装饰图，不能递归。备案链接、编号、可读文本不丢失。0粉丝显示暂无；1/多粉丝展示真实计数；没有真实粉丝头像数据则使用文字或中性图形，不能用本人头像冒充。无需扩展粉丝接口。

## C08 对比规格（F08，前端）

共享类别适用的规格展示逻辑：RISER显示厚度heightMm（12.7/3.175 mm）；HARDWARE显示lengthMm等已有字段，缺失明确未知。数字null/undefined未知，合法0不被truthiness吞掉，按原数值保持精度。详情/比较一致；不由厚度断定螺丝长度或物理兼容，不扩展比较API。

## C09 参考小计下界（F09，前端）

当totalCents为null、knownSubtotalCents与demand.budgetCents均为有效非负分整数，且已知小计大于预算，直接计算差额。60000/78620显示“按当前参考明细，已知部分至少超预算186.20元”。同屏保留总价未知、缺价项与数据不足。相等/小于预算不宣称完整可行；缺少有效预算不显示差额。不写回budgetDeltaCents，不新造完整总价，不请求额外后端字段，不自动加预算。非参考模式若涉及负价格/抵扣，不推广此参考下界规则。

## C10 资料与分区（D01，后端资料→前端）

后端仅核对正式equipment.json/normalized-equipment.reference.v1.json已有来源及必要的有据补足；字段记录实体键、原文/URL、采集日期、适用规格、RECORDED/VERIFIED、变更依据。补不全则留下缺口，不能用合成国内价、换算海外价或无来源物理阈值完成。

HW-002/003已有明确长度/8钉8母原文可逐字段审查转写；HW-001多变体仍不替用户选。21可用国内参考价与型号错配排除保持；不要求实时库存/运税/涨幅证实。299历史缺口分为参考模式仍阻塞、仅精确采购门槛和记录待核实，不要求将全部清零。

现有真实API具priceComplete。前端分区沿用BoardCalculationService.feasible既有谓词：priceComplete===true且validationState为VERIFIED/MANUFACTURER_COMPLETE/REFERENCE_ESTIMATE，才可进入相应完整结果区，且总价必须为有效分整数；参考结果明确标参考。INSUFFICIENT_DATA进入待补区；INCOMPATIBLE另显阻断，不进入完整区；未知状态保守显示待确认，不能当通过。不凭title/knownSubtotal判完整；不能把单纯total非null视为兼容。完整分区为空显式说明；不足分区显示来源与缺口。搜索截断/最低范围说明保留。禁止升级RECORDED成VERIFIED、宣称全目录通配或保证可购买。

## C11 展示分组（UX01，前端）

先结论/预算/差异，再可展开依据。相同解释但不同type/ruleKey/版本/状态/范围/来源不删除；合并展示需能展开完整原检查。明确不兼容、资料不足、已知超预算下界不折叠隐藏。保持引用到源记录；不改算法/物理阈值。

## C12 有界体验（UX02，前端）

公告暂无endTime，默认显示发布绝对日期和“时效待确认”；较旧的相对日期活动文案标历史活动通知，不计算虚构截止日/自动删除。首页与商品详情链接按实际URL区分“站点首页/参考平台/商品来源”，不承诺购买直达。

障碍/安全提示在展示层用共享已知词映射为中文，未知原文保留；后端tag搜索/关联逻辑保持（不把英语键改中文导致关联失效）。无收藏入口的空态改为可执行建议。匿名打卡输入区上方预告需登录，提交鉴权保留；不引入无依据自动保存。轮播圆点加可访问名称、按钮类型和当前状态（aria-current或适合语义），不做页面重设计。

## 总负责冻结补充（优先于草案中的建议措辞）

- C01不能依赖地图或地图SDK成功来获得地区选项。优先审查并复用可独立请求的地区资料；如新增随包行政区静态资料，记录固定来源/版本/覆盖/使用许可，仅加最小必要文件，不新增运行依赖。加载失败与真实无下级分别表示。不新增省份查询/迁移，省份只用于级联选市并明确标注。
- C03/C04/C05/C06按以上JSON形状正式冻结为向后兼容的新增只读契约。原API外壳/字段/鉴权不删除，路径与方法固定；所有未列明调用者也要核对兼容，不为旧字段作假回填。
- C04 `score` 使用JSON数字或null，`count` 非负整数；统计集合与公开评价列表的有效记录一致。0条不能变成0分差评，获取失败不能变成真实0条。保留旧持久化值但不再用它们作为本站评分显示或排名依据。
- C08/C09不扩展选板API或改算法；C09仅当前REFERENCE明细成立，用分整数计算，不把参考估计宣称真实市场最低价保证。
- C10完整参考区的最小谓词：kind=ASSEMBLY、pricingMode=REFERENCE、priceComplete===true、totalCents为非负安全整数、validationState=REFERENCE_ESTIMATE，且missing为空、checks无INCOMPATIBLE/INSUFFICIENT_DATA等阻断；若数据结构不合契约一律不能升级到完整区。精确模式VERIFIED/厂家整板按原模式分别标注，不混称参考方案已完成市场/物理核验。预算超限另标，不得称预算内可用；资料不足与明确不兼容分开解释。
- C10原始equipment.json及原始SQL、现有正式规范库v1保持原字节。后端有明确证据可转写的HW-002/003字段以新增补充候选与逐字段来源清单交付，不自动替代原目录/不改变生产。没有价格/适用规则继续列缺口；不得用合成数据关闭资料补齐。资料治理实施完成与仍无完整组装方案要分别记录，最终PR披露剩余真实缺口。
- UX01仅归并展示：保持全部不同type/key/version/state/source的依据可展开查阅，缺价/不兼容/预算下界始终可见。
- 本批只提交PR，最终独立审查角色可受控commit/push/createPR及等待准确head全CI；开发阶段禁止commit/push。所有角色禁止合并部署及生产写入。
